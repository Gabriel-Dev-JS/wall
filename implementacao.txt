7. Uma coisa MUITO importante: não deixe o Claude inventar tudo
Esse é provavelmente o maior conselho que eu daria para alguém começando com Claude Code.

Você não precisa saber programar profundamente, mas precisa ser o dono da arquitetura e das regras do produto.

Por exemplo, decida:

Uma despesa de R$ 50 é armazenada como 50.00 ou 5000?

Eu recomendaria armazenar dinheiro como inteiro em centavos:

R$ 10,50 → 1050
R$ 99,90 → 9990

Isso evita vários problemas de precisão de ponto flutuante.

Então você pode dizer ao Claude:

Valores monetários devem ser armazenados como inteiros em centavos. Nunca utilize float para representar dinheiro.

Esse tipo de regra é muito importante.

8. Crie um "contrato" para o Claude
Eu também faria você ter um arquivo de instruções do projeto.

O Expo atualmente cria arquivos de contexto como AGENTS.md e CLAUDE.md em projetos novos, e documenta o uso do plugin oficial do Expo para Claude Code. 
D
Documentação Expo

No CLAUDE.md, podemos colocar coisas como:

# Projeto Minhas Contas

## Objetivo

Aplicativo mobile para controle simples de receitas e despesas.

## Tecnologias

- Expo
- React Native
- TypeScript
- expo-sqlite

## Regras

- O aplicativo deve funcionar 100% offline.
- Não criar backend.
- Não utilizar Firebase.
- Não utilizar Supabase.
- Não utilizar APIs externas.
- Valores monetários devem ser armazenados em centavos.
- Código deve ser TypeScript.
- Separar lógica de negócio da interface.
- Evitar dependências desnecessárias.
- Priorizar simplicidade.

Assim, conforme o projeto cresce, o Claude tem um contexto permanente.

9. E o Claude consegue corrigir erros?
Essa é uma das partes mais interessantes.

Imagine que você rode:

npx expo start

e apareça um erro.

Você pode simplesmente falar para o Claude:

Estou recebendo este erro:

[cole o erro]

Analise a causa e corrija o problema. Antes de alterar arquivos, explique brevemente o que está causando o erro.

Ele consegue analisar o código e trabalhar em cima disso.

E você pode inclusive pedir:

Rode os testes depois da correção.

Esse fluxo de:

implementar → executar → encontrar erro → corrigir → testar

é onde um agente de programação fica realmente útil.
